# 148 rps, which is 0.45x the analytic rated capacity of 328 and, at freeze time, almost exactly the

# least_requests already collapsed to 0.2011). A replica's queue is rarely empty here and the fleet
# still has headroom, so a misplaced request waits behind work instead of being absorbed.

# Which "rated capacity" this is anchored to, and why it matters: `Scenario::rated_rps()` is a
# saturation figure from the cost model — device-seconds per request against the fleet — and it says
# 328 rps. Measured, this mixture cannot hold any usable SLO above roughly 150. The analytic number
# therefore overstates SLO capacity by about 2.2x, and this file is anchored to the measured one so
# that the scenario is at the edge rather than beyond it. The gap itself is a finding, recorded in
# docs/arena-implementation.md, and it is exactly what docs/arena.md section 3's declaration mechanism
# is supposed to price: a policy that declares the cost model's number breaches the gate everywhere.
#
# Why it is in the suite: it is the regime the objective in docs/arena.md section 1 is actually about,
# "as long as the load is under a rated load capacity". A policy is allowed to fail above capacity and
# is not allowed to fail here, so this scenario, not the overload one, is where the SLA gate bites.
